# Pro 项目购买链路

当前实现采用服务端模拟付款校验。客户界面使用正常的报价、付款和开通文案；后台和数据库保留模拟标记，不发生支付渠道扣款，不把模拟付款写成实际到账。

## 客户流程

1. 提交 Free 项目，自动完成出海机会分析和必要追问。
   新用户可免登录领取一次完整单轮试用，当前浏览器限领一次；注册用于保存成果，非试用前提。试用后购买的三轮为额外三轮，详见[免登录试用规则](pro-new-user-trial.md)。
2. 在项目页查看当前范围的 Pro 报价，确认后创建项目订单。
3. 点击「付款并开通 Pro」，服务端根据已保存的订单金额和报价版本执行校验。
4. 校验通过后，在同一数据库事务中保存付款校验记录、开通当前项目并加入策略执行队列。不经过申请、老板批价或人工核款。
5. 客户确认定位及公开发布；保留证据检查。随后可启动增长复盘，核对交付清单并验收。

新购套餐覆盖同一产品、同一目标市场的三轮完整验证。第一轮随付款自动启动，后两轮由客户在复盘后确认开启；同轮改稿和失败重试不扣轮数。不会修改账号会员等级，也不会开通其他项目。原账号 Pro、密钥及已付款订单的权益保留。未付款旧提案进入同一自助购买入口，不再要求老板批价；已有付款或凭证的历史订单不能覆盖或重复购买。

## 计价

计价版本 `mimo-cn-2026-09-22-service-v3`，默认标准价 **¥99／项目／3 轮**。按当前实际路由估算付费阶段新增工作，已完成 Free 的研究与解析优先复用，不重复运行。

- 三轮套餐增量预算：630K 输入、130.5K 输出；含 1.25 重试预算约 950.6K token。输出预算包括推理消耗。
- 研究规划用 Flash，证据综合和定位用 Pro，页面与渠道同一次 Flash 调用，复盘和客服用 Flash；全部采用实时费率。缓存收益暂按 0 估算。
- 三轮补查合计预算 36 次，暂按附件海外搜索费率 ¥0.0355／次计；实际取决于渠道，免费公开接口不应冒记为付费搜索。
- AI 预算 ¥4.10625；加基础设施假设 ¥5 得直接预算 ¥9.10625；再加获客、异常和维护准备金假设 ¥40，内部预算 ¥49.10625。准备金不是已发生支出或必需人工审核。
- 价格公式为 `max(套餐底价, 向上取整到元((AI预算 + 基础设施 + 经营准备金) × 倍率))`，默认 `max(99, ceil(49.10625 × 2)) = ¥99`。
- token 是内部预测，当前不是自动扣费配额，也不是承诺的硬上限。没有实测完整链路的成本保证；具体计算、样本局限和经营敏感性见 [定价测算](pro-pricing-service-v3.md)。
- 订单保存不可变计价快照，并绑定项目、需求版本、范围和轮次。调价不修改已确认的待付款或已开通订单。
- 已有真实付款或任何凭证的历史订单不得转为新购买；未付款旧报价由客户重新确认新范围与价格，复用订单 ID、递增版本并审计保存旧报价与提案。

## 配置与迁移

`firstcustomer/.env.example` 中新增：

```dotenv
PAYMENT_MODE=simulated
PRO_MIN_PRICE_FEN=9900
PRO_MARKUP_PERCENT=200
PRO_INFRA_FEN=500
PRO_RESERVE_FEN=4000
```

生产环境必须显式设置 `PAYMENT_MODE=simulated` 才会开放该流程；未配置时关闭支付。开发环境默认使用模拟通道。`disabled` 可关闭新的报价购买与付款校验，不撤销已开通项目。

运行 `npm run db:migrate` 应用 `0014_project_checkout.sql` 及试用所需的 `0015_customer_pro_trials.sql`、`0016_guest_pro_trial.sql`，再启动 Web 和 worker。更改支付模式或计价配置后需重启 Web。旧状态通过兼容购买入口和排队任务恢复，不在 GET 页面加载时写库。已有环境显式设置了 `PRO_MIN_PRICE_FEN=29900` 的，需将该环境配置改为 `9900` 后重新启动或部署，默认值不会覆盖显式配置。

## 内部记录和重试

- `orders.pricing_snapshot` 保存完整计价快照；`payment_mode=simulated`。
- `purchase_payments` 保存校验凭据，`simulation_pending → simulation_active` 是内部订单状态。客户页面不展示这些内部状态或通道引用。
- 模拟结果不写入 `payments`，不计入真实外部订单、收入、访问或线索指标；实际发生的模型成本仍计入成本。
- 报价确认与付款均锁定项目；重复提交、并发付款只开通和入队一次。
- 校验订单、金额、币种、支付凭据和项目范围；客户端不能通过传入金额或“已支付”标志开通。
- 队列写入失败会回滚校验结果和开通；客户可用原订单重试。
- 已归属账号的购买项目要求本人登录；访客购买继续使用原专属凭据。

后续真实支付接入点为 `src/payments/provider.ts`。正式接入还需要创建真实支付交易、回调验签及主动查询、超时与退款处理，以及真实收款入账；不能直接把此模拟校验器改名后用于实际收费。

## 三轮套餐实现

购买快照保存 `includedRounds=3`；缺失该字段的历史快照按单轮保留。授权校验允许当前项目轮次落在购买起始轮到起始轮+2 内，仍严格绑定需求和范围版本。新价格及套餐默认值不修改已接受的旧快照。

下一轮入口仅在本轮复盘与交付检查完成后可用。无需老板审批，也不要求实验必须失败；样本不足仍可以在复盘后调整原范围内的假设。可先验收一轮，再使用剩余轮数。新一轮不会自动撤下旧公开页面，新版本仍需客户确认发布。

开启下一轮在一个数据库事务内锁定项目、核对购买与付款、验证剩余轮数、递增项目轮次、保存 `pro_round` 审计并入队。客户端的剩余次数不被信任；旧轮次表单重放不再递增，入队失败回滚。已经开始的一轮在模型失败后继续重试，不扣下一轮。轮数用完后仍可查看历史成果并完成本轮修改。

三轮套餐本地验证：275 项测试、类型检查、生产构建通过。浏览器核对前两轮剩余数，三轮连续交付与用尽拦截由集成测试覆盖；验收后证据过期不影响启动尚未使用的轮次。临时测试项目已清理。详细范围与验证限制见 [V3 套餐说明](pro-pricing-service-v3.md)。
