# 当前角色与业务流程约定

更新：2026-11-08。本文描述账号权益与项目购买流程；历史报价项目继续兼容原有记录。项目购买当前使用服务端模拟校验，后台与真实收款隔离。详见 [Pro 购买链路说明](pro-purchase-implementation.md)。

## 角色与入口

| 使用者 | 入口与凭据 | 可操作内容 |
| --- | --- | --- |
| 免登录访客 | `/account`、浏览器试用凭据 | 创建 Free 项目，查看自己的机会报告；有效试用凭据可在登录后归档 |
| Free 客户 | `/login`、`/register`；邮箱密码 | `/account` 查看本人项目，基础研究、补充信息、查看报告、确认报价及购买项目 Pro |
| Pro 客户 | 同一客户登录；数据库中的有效账号权益 | 默认进入 `/account/pro`；使用本人项目的研究、定位、英文页面与渠道、增长复盘模块 |
| 首客老板 | `/admin/login`；独立内部账号密码 | 公司经营、历史订单报价与核款、项目异常、客服升级、经营知识和审计 |
| 海外访客 | `/launch/[slug]`；无需账号 | 仅访问已公开页面，自愿留资；不能进入客户项目或内部经营台 |

Free、Pro 是同一种客户身份的不同权益，不是老板角色。`owner` 是登录权限名称；历史决策中的 `founder` 表示老板操作。`isOwnProduct` 仅标记首客自有项目，不授予权限。

客户的 `account.<项目 ID>` 入口必须同时验证登录和归属。原有私密项目凭据保留历史兼容；项目使用账号 Pro，或购买项目已归属账号后，即使持有原凭据，也必须登录所属客户账号。未归属的访客购买继续使用原专属凭据。

供给方、需求方、接单方等双边交易角色目前只存在于设计文档，尚无可登录的对应业务端。不能把设计稿当成已经实现的流程。

## 主流程

- Free：确认需求 → 自动入队 → 研究／必要追问 → 出海机会报告 → 可确认报价并购买当前项目 Pro。
- 项目 Pro：确认自动报价 → 付款校验 → 自动开通本项目并入队 → 定位 → 客户确认 → 英文页面与渠道方案 → 客户确认公开 → 收集反馈 → 客户启动复盘 → 完成交付并验收。无需申请审批或逐单人工核款；一次购买只覆盖当前项目范围的一轮验证。
- 账号 Pro：登录识别权益 → 新建项目或选择本人项目模块 → 研究 → 定位方案 → 客户确认 → 英文验证页与渠道素材 → 客户确认公开 → 收集真实反馈 → 客户从增长模块启动复盘 → 查看复盘；存在下一轮假设时，再由客户确认下一轮。

模块共享同一个项目状态和材料，不会为每个入口复制一套任务。进入尚未具备上游材料的模块时，先完成上游研究；模块权限不绕过证据检查、客户发布确认或异常处理。

账号 Pro 不经过初步报价、付款截图、老板开通审核，也不伪造老板审批。模型失败、资料打回超限、投诉与退款等异常仍由内部经营者处理。账号过期或撤销后保留历史资料，高级任务等待权益恢复；客服仍可使用。

## 历史授权与账务

- `customer_memberships` 决定账号版本；前端参数、密钥和项目链接不能直接修改账号版本。
- `projects.pro_access_source = account` 与订单 `account_active` 表示使用账号权益，不是实际支付。
- 项目密钥 `key_activated` 只授权该项目，不自动升级整个账号；历史双边审批继续保留。
- 历史报价／实付项目继续按原订单与审批合同处理，避免重解释已接受条款。
- 实收只来自实际 `payments` 记录；真实客户经营汇总排除测试账号与模拟支付项目的订单、实收与增长。模型实际消耗仍计入成本。测试权益、密钥、报价、报名均不能计为收入。
- 新购买订单保存版本化计价快照；当前底价沿用可配置的 ¥299。`purchase_payments` 保存模拟校验记录，只有校验成功才开通对应项目，不修改账号会员等级，也不写入真实 `payments`。客户页面使用正常购买文案，后台标明模式。

## 办公室人物与执行任务

| 形象 | 后台任务或分工 | 权限边界 |
| --- | --- | --- |
| Lumi Agent，奶油兔 | 引导问答、`quote`、`support` | 引导不等于提交；报价任务仅供历史流程；不能核款或替客户确认 |
| Nori，猫头鹰 | `research:plan`、`research`、`vision` | 查找与记录证据、阅读截图，不审批或保证市场需求 |
| Fino，狐狸 | `strategy` | 生成定位与验证方案，由客户确认 |
| Milo，松鼠 | 新项目订单校验；历史 `receipt` | 新项目校验成功后自动开通；历史截图仍不能单独证明到账 |
| Kito，浣熊 | `launch` | 准备页面与素材；客户确认后才公开页面 |
| Pogo，青蛙 | `growth` | 根据真实指标复盘；文案准备不代表渠道已执行 |
| Yuki，绵羊 COO | `standup`、`weekly` | 生成站会与经营建议，不自行审批或派发业务决定 |
| Toby，金毛老板形象 | 内部经营者的可视化入口 | 形象不是拥有权限的 AI 账号；权限来自真实内部登录 |

MiMo AI 是模型技术展示名。人物动画由项目状态、实际运行任务与交接记录驱动；首页办公室明确为情景演示。动画本身不会执行后台任务。网页进程负责入队，本地必须另有一个 worker；云端由持久队列和受保护回调执行。
