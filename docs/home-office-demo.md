# 首页动态办公室

首页采用上方整幅场景、下方两列三行 Agent 介绍的结构，继续使用已有纸面排版与木质森林办公室素材。

## 形式选择

选择 Canvas 2D 绘制独立角色，叠加 HTML 交互按钮和文字。视频适合固定镜头宣传，修改对白或响应角色点击需要额外的交互层与重新制作。本场景需要按角色切换片段、暂停后续播、改变交接路线，所以采用实时场景。未增加新运行库或调用生成模型。

办公室背景由 Next Image 单独加载，动物使用已有八列两行透明图集；Canvas 只重绘角色、文件、交接确认和工作屏幕。角色介绍复用已有独立 IP 插画图集。

## 情景与交互

六幕分别演示接待交给研究、研究交给策略、前台提交凭证给财务、策略交给发布、发布交给增长、增长反馈给策略。每幕包括桌前工作、经过走廊走动、双方接件和返回工位，配脚本对白。点击工位或角色介绍切换相关片段；角色介绍按钮返回场景并将焦点交给演示区。支持暂停、续播、六幕选择，以及“处理任务 / 当面交接 / 接手开工”阶段跳转。

六位服务角色依次为 Lumi（露米）、Nori（小枭）、Fino（赤狐）、Milo（松栗）、Kito（蓝狸）、Pogo（芽芽）；辅助角色为金毛老板 Toby（托比）和绵羊 COO Yuki（云团）。名字使用品牌配置，角色卡、对白、工位与任务标签同步更新。

脚本是协作机制示意，不读取或更改真实客户进度，不调用 Agent，不产生模型成本，也不创建报价、付款、发布或审批记录。凭证识别与老板确认实际到账分开说明，发布仍需要审批。右上角的老板与 COO 保留为辅助角色，六位服务角色组成两列三行。

## 性能与可访问性

- 角色画面最多每秒绘制 30 次，设备像素比上限 1.5；React 仅在片段或交接阶段变化时更新。
- 离开可视区域、切入后台或手动暂停时取消后续帧，恢复后从原位置继续。
- 减少动态偏好下提供静态角色、完整对白与手动选幕。Canvas 不可用或图集加载失败时保留 CSS 静态角色与重试入口。
- 文字、角色说明、选幕与控制由 HTML 承载；Canvas 作为辅助视觉，不要求读屏读取像素内容。
- 窄屏角色介绍保留两列三行；地图最小宽 760px，可横向查看并跟随当前协作。场内气泡和下方完整交接画面共同解释协作。

采用的原生浏览器机制可参考 [MDN Canvas 性能建议](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas)。

## 工作标识与设计交付

桌面和脚底不再绘制工作光圈；工作状态由上方任务牌、三条动态工作条、头部/手部动作和职责工具表达。单幕 20 秒，接收方回工位后保留七秒继续工作。下方以双角色、交付文件和方向线呈现交接，六位动物组成可点击片段导航；Free 起点与可选 Pro 路线独立说明。
