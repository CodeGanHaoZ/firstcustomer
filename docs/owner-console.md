# OPC 老板经营台与后端检查

2026-11-08。依据 PRD V4.2 的 2.2、2.5、6.9、6.11、6.12 节及当前 `PRODUCT.md` 的 Free / Pro 流程。老板指首客 OPC 公司的实际经营者，不是购买服务的客户。

## 入口与使用

- `/admin/login`：独立内部账号和密码；成功后进入 `/admin/owner`。
- `/admin/owner`：经营总览、决策收件箱、批价、待客户确认事项、运行与成本、项目与订单搜索。
- `/admin/audit`：按项目、事项、老板或客户筛选决策与项目流转，每页 25 条。
- `/admin/access`：当前老板账号、身份与 11 项内部权限；供需账号设计边界。
- `/admin`：保留 AI 办公室；定位、发布、核款、交付等详细审批从收件箱进入对应项目面板。

经营台读取真实数据库，每 30 秒刷新；页面隐藏或焦点在表单内时暂停刷新。待办优先显示超过 24 小时的事项，再按异常、核款、批价等排列。暂停项目显示恢复入口，不混入批价队列。

批价时，打开「审阅报价」，核对当前版本的范围、交付清单、周期与条款，调整批准金额。确认后等待客户接受；退回必须说明原因，并重新起草、重新审批。旧版本、重复提交与暂停项目由服务端拒绝。批准报价不会产生实收。

核款通过「核对到账」进入项目凭证面板，核对实际到账后再确认。付款截图本身不等于到账。

## 技术文档中的老板权限

| 闸门 | 能力与入口 | 记录 |
| --- | --- | --- |
| ① 公司宪章 | 未确认时进入公司待办，前往公司卷宗设置 | 宪章版本、老板决定 |
| ② 声明红项 | 程序拦截；失败与升级任务进入异常待办 | Agent 检查记录；人工裁决写入决定 |
| ③ 定位与范围 | 老板审阅定位，客户单独确认 | 双方决定、成果版本 |
| ④ 对外发布 | 老板与客户确认页面和渠道材料 | 双方决定、页面版本；执行凭证另记 |
| ⑤ 价格与条款 | 直接批价、退回 | 报价版本、当时金额与完整提案快照 |
| ⑥ 实际到账 | 核款待办跳转付款凭证 | 报价金额、实收、付款与凭证 ID、差额说明 |
| ⑦ 高风险客服 | 投诉、退款等升级进入异常与客服待办 | 问题 ID、老板回复快照 |
| ⑧ 经营周报 | 未决策周报进入公司待办 | 周报 ID、继续／调价／收缩服务的决定 |
| ⑨ 交付或下一轮 | 复盘进入方案与交付待办 | 当前成果核验、老板决定、客户验收 |

客户账号、客户专属链接和内部账号保持隔离。新增页面在查询业务数据前调用 `requireAdmin(permission)`；批价等写操作分别校验明确的内部权限。审批完成仍只返回对应项目或固定 `/admin/owner`；登录返回使用该角色的站内路径白名单，不允许外站跳转。

本机老板账号为 `hifirst`，角色 `owner`，凭据位于 `firstcustomer/.local-admin-credentials.txt`（Git 忽略、0600），不在页面或日志显示密码。`npm run owner:provision` 可以重复分配并保留已有密码；只有显式传入 `--rotate-password` 才更换已有密码。账号由部署配置管理，暂无多管理员授权界面。实际内部身份不会从客户注册参数或项目链接取得。

## 后端检查结果与修复

原后端已具备 PostgreSQL 持久化、事务状态机、版本审批、证据检查、任务重试、客服升级和公司周报。本次在同一套业务表和状态机上补齐经营入口，并修复以下问题。

| 发现 | 处理 |
| --- | --- |
| 待办、收款、订单和审批分散 | 统一经营台与可筛选的操作记录 |
| 客户成效混入自有产品 | 排除自有产品、未发布页与测试线索；首条有效线索采用相同口径 |
| 增长汇总逐页面执行 4 次查询 | 改为数据库聚合，保留每页内访客去重的含义 |
| 旧版人工收款允许重复记账 | 业务层金额校验、项目行锁、检查已有实收，并发只允许一笔 |
| 旧版已付款订单可直接改价 | 阻止已接受、已付款或密钥开通订单改价；旧版报价递增版本并保存决定 |
| 暂停时商业流程仍可推进 | 批价、上传付款截图与确认到账增加暂停检查 |
| 报价只有文字原因，无法还原原条款 | 保存金额与提案快照；核款保存付款和凭证关联；客服保存回复快照 |
| 人工分钟缺少业务层整数校验 | 拒绝负数、小数、非有限数与超出数据库范围的值 |

复用现有 `decisions.snapshot`，本次无需新增数据库迁移。已有未提交的 Pro 密钥、需求与交付相关修改继续保留。

## 统计与记录口径

- **外部客户实收：** 已写入付款记录、且未标为自有产品的金额。报价、客户接受、上传截图和 Pro 密钥开通不会自动计入。
- **待收款：** 外部客户已接受且未取消订单的报价，与实收分别显示。
- **客户成效：** 曾经发布的外部客户页面，排除测试线索；不把线索称为成交或首客收入。
- **模型标价与人工：** 全公司累计，含内部研究。未计价任务另列，模型标价不代表账单实扣。
- **操作记录：** 合并 `decisions` 与 `state_transitions`，按时间和 ID 稳定分页；不是所有数据库写操作的完整审计。历史无快照时明确说明，不补造。

## 验证与范围

`tests/owner-dashboard.test.ts` 使用独立 PostgreSQL 执行真实迁移，覆盖待办分类、超时排序、数据隔离、统计口径、暂停保护、过期版本、并发批价、重复记账、快照与日志分页。原有业务测试继续覆盖报价至收款、双方审批、发布、需求版本与交付。

浏览器核验使用独立本地数据库，样例标注「测试数据」，不修改现有业务数据库。模拟金额不代表真实收入。

本次结果：12 个测试文件、207 项测试通过，类型检查、ESLint 和生产构建通过。浏览器验证了未登录跳转、老板登录、修改并批准报价、审批后不增加实收、日志筛选与快照，以及 1440px 桌面和 390px 手机的中英文布局；浏览器控制台无错误。新增页面的次要文字在纸面背景上对比度约为 5.07:1。

当前为单个 OPC 老板的内部账号，没有新增多管理员 RBAC 或防篡改审计存储。支付仍为人工核对，没有银行回调、自动退款或自动对账。本次不包含线上备份恢复、云端告警与真实支付平台核验，不能用本地测试宣称这些已具备。生产部署尚未执行。
