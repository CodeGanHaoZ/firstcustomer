# 设计规范

基准：`d2c09c9`。以下数值对应已实现的 CSS；局部计算值以 [tokens.json](tokens.json) 与源代码为准。本文件限定办公室与服务路线，不替换全站视觉体系。

## 设计意图

工作状态应让人知道“谁正在做什么”，而不是在家具上叠一个发光底座。办公室下方需要呈现“角色携带成果交给下一位”的关系，文本依次说明当前职责、交付物、后续动作与用户决策。

### 信息顺序

1. 当前任务与预期产物。
2. 下一位伙伴与启动条件。
3. 可暂停、可跳转阶段的动态办公室。
4. 双角色交接画面：发起者、文件、接收者。
5. 用户需要确认什么。
6. 六段可点击协作导航。
7. 六位 Agent 的职责与产物，固定两列三行。
8. 独立的 Free / Pro 完整服务路线。

## 字体与排版

沿用 `editorial.css` 的字体栈：中文衬线优先 Songti SC / Songti TC，英文衬线回退 Georgia；界面正文沿用现有 sans 栈。没有新增字体下载。不同系统的字体回退可能使断行不同，不把 macOS 截图的换行当成固定字符位置。

| 角色 | 桌面 | 600px 以下 | 行高/规则 |
| --- | --- | --- | --- |
| 交接主标题 | `clamp(25px,2.9vw,36px)` | 24px | 1.5，`text-wrap: balance` |
| 双角色姓名 | 25px；600-900px 为 21px | 25px | 1.35，衬线 |
| 角色对白 | 16px | 16px | 1.9，桌面最长 34ch |
| 用户决策说明 | 15px | 15px | 1.85，最长 70ch |
| 六幕导航标题 | 15px | 13px | 1.5 |
| 交付物/状态标签 | 12-13px | 11-12px | 紧凑信息角色 |
| 服务阶段标题 | 24px | 23px | 1.45，衬线 |
| 服务阶段说明 | 16px | 15px | 1.85 |

标题用字重、尺寸与空间建立层级；说明与对白使用完整句子。不要把所有说明压到 11-12px。用户填写内容、报告原文不随语言切换重写。

## 工作中标识

- 首页：工位牌持续可见；当前活动角色用深绿牌、明确的“正在工作/正在交接/正在接收/接手开工”与三条工作条表达。
- Canvas 的桌前工作角色缩放为 1.12；通过头部转动、前爪敲击和职责工具补充动作。其他角色适度降低透明度。
- 客户/经营台：仅真实运行任务显示工作状态；角色高度 15.7%，普通角色 14%。工作牌最多占地图宽度 19%，避免英文牌子遮住相邻工位。
- 简短英文工作牌使用 `Working · Evidence / Positioning / Receipts / Page / Review / Brief`；完整任务说明保留在引导区。
- 真实办公室工作条 900ms 交替缩放，暂停、离屏/后台、离线或减少动态路径分别按现有逻辑停止。不要让等待审批的角色表现成正在计算。

## 桌面交接画面

`.office-relay` 为统一深松绿画面，圆角 12px，内边距 `clamp(1.25rem,3.2vw,2.5rem)`。标题区用有意义的场景编号 01/06 与主标题；不是全站装饰性章节编号。

`.relay-exchange` 三列为 `minmax(0,36ch) / minmax(140px,176px) / minmax(0,36ch)`，使用 `justify-content:space-between` 均分两侧留白，列间距 1.5rem。左右各放真实 IP 插画、姓名、工位与完整对白；中央文件纸张约 108px 宽、104px 最小高，配方向线与交付物名称。用户决策在底部独立成行。完成接收后，文件轻移 12px 并从 -4deg 转为 4deg，650ms 自然减速。

六幕选择为六列连续导航，每个节点包含对应主责动物、编号、片段标题、双方英文名和交付物。选择后的背景、标题下划线与 `aria-current=step` 一起表达当前片段。角色卡的姓名下划线在悬停或当前角色状态出现；保留 `d3e1684` 的实现。

## 移动端与中间断点

| 范围 | 行为 |
| --- | --- |
| 大于 900px | 交接三列，中间 160px；六幕导航六列 |
| 601-900px | 中间缩为 116px，姓名 21px，IP 宽 64px |
| 600px 及以下 | 发起者、文件、接收者竖向排列；文件简化为横向纸条；六幕导航三列两行 |
| 所有窄屏 | 六位 Agent 介绍仍为两列三行 |

首页办公室最小绘制宽 760px，外层可横向查看，镜头跟随当前协作；手动拖动/滚轮后停止自动跟随，按钮可恢复。真实项目地图最小宽 680px。不要通过把整间办公室缩成小缩略图来“适配”手机。

390px 设备测试中，浏览器内容区受滚动条影响为 375px；截图组件约 335px。验收要记录内容宽度，不只记录设备预设宽度。实际采集值见 `screens/capture-metadata.json`。

## 完整服务路线

桌面左侧为深绿 Free 起点，右侧为 Pro 五个阶段的纵向路径；不表示用户会自动进入付费服务。左侧在桌面 `top:110px` 粘性定位，移动端恢复普通文档流并排在 Pro 前面。阶段标题、现有业务说明和对应角色保持绑定；付款与发布仍由业务记录及人工确认决定。

## 设计继续细化时的约束

- 保留原始八位动物、英文名与六个核心岗位映射。
- 不把协作演示包装成真实后台遥测，不增加虚构完成百分比、预计耗时或工具调用数。
- 不让无证据的声明进入英文公开页，不用动画跳过报价、到账、定位或发布确认。
- 保留键盘焦点、44px 操作触点、静态降级与减少动态偏好。
