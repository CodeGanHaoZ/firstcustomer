## 设计验收

- [ ] 桌面/脚底没有光圈，动物与家具透视自然；行走投影不误当工作中标识。
- [ ] 工作牌持续可见，状态文字、三条工作条与职责工具同时可识别。
- [ ] Lumi / Nori / Fino / Milo / Kito / Pogo 的姓名、形象、岗位和交付物一致。
- [ ] 交接画面能读出发起者、交付文件、接收者与用户需要确认的事情。
- [ ] 标题、姓名、对白、说明和元信息的层级明显；不把正文统一缩成标签字号。
- [ ] 六幕导航有六位正确主责动物，选中态明显，点击与上方场景同步。
- [ ] 六位 Agent 介绍保持两列三行；姓名悬停下划线与当前角色状态保留。
- [ ] Free 起点与可选 Pro 路线清楚区分，不暗示自动进入付费服务。

## 交互验收

- [ ] 每幕可看到处理、送件、核对、接收、返回与下一位开工。
- [ ] 点击三个阶段分别跳到 0 / 8000 / 13000ms。
- [ ] 暂停后画面和工作条停止，文字仍完整；恢复后继续。
- [ ] 离屏与页面后台不继续消耗动画帧；回到页面不跳过阅读中的确认步骤。
- [ ] 手机可手动左右看办公室，手动查看后不被镜头拉回；“跟随当前 Agent”可恢复。
- [ ] 中文/EN 切换保留片段与进度，界面文案完整，产品/报告原文不被改写。
- [ ] 减少动态模式可用静态姿态理解流程；Canvas 失败仍能选幕、读对白、重新加载。
- [ ] 键盘可触达按钮，焦点清楚，操作触点至少 44px。

## 真实状态验收

- [ ] 未运行的排队任务不显示“工作中”。
- [ ] 等经营者、等客户、等到账、等数据分别讲清楚，行动入口落到正确区域。
- [ ] 暂停但尚在收尾的任务，显示收尾后暂停，不暗示继续启动下一步。
- [ ] 真实任务牌在英文下不与邻近工位重叠。
- [ ] 演示不调用模型、不创建订单、不确认到账、不越过定位或发布审批。
- [ ] 客户查看闲置工位后，可返回当前工位；经营台工位仍打开对应业务详情。

### 已知后续项，交给前端评估

在 320px 英文页面，**已有首屏 CTA 的最小宽度会让整页横向溢出**；该问题不来自本次办公室组件。采集时视口内容宽 305px、整页宽 358px，交接面板宽 265px 且自身没有溢出。此次按设计交接记录，未扩大范围修改首屏，不能据此宣称全站已完成 320px 英文适配。

系统级减少动态与屏幕阅读器仍建议在目标设备作人工复核；包中已有对应实现及检查项，不把源码检查冒充完整辅助技术测试。
