# 首客资料库

入口：[线上资料库](https://hifirst.vercel.app/admin/knowledge)。使用经营者账号进入经营台，点击左侧「资料库」。客户的邮箱账号没有经营台权限。

## 已准备的基础资料

首次初始化提供 14 篇资料：6 篇公开服务说明与 FAQ，8 篇内部品牌、研究、定位、发布、复盘与运营规范。资料来自现有首客服务流程和代码，没有填入虚构市场案例或客户记录。

「补齐基础资料」只新增缺少的初始条目，不覆盖已编辑内容，也不会重新发布已撤下的资料。

另外已整理用户提供的公司卷宗 v2 交接包：9 篇内部卷宗规范、1 篇 Lumi 公开服务说明。这批内容属于规范参考，示例订单、收入、市场证据与审批不作为实际业务数据导入。原件、版本对齐说明和整理包保存在本地 `firstcustomer/.local-knowledge/context-hub-v2/`（已忽略），内部正文不随公开 GitHub 仓库发布。来源文件名、校验值和核对说明随文章保存。

## 新建与导入

1. 点击「新建资料」，填写标题、分类和正文。
2. 可以直接粘贴文字，或导入 UTF-8 编码的 Markdown / TXT 文件。文件最多 64 KB，正文为 10–12000 字；导入会替换当前正文。
3. 选择公开或内部范围，并勾选可以使用资料的 Agent。
4. 补充来源链接、来源说明和核对日期。会变化的价格、渠道规则或政策应设置到期日期。
5. 保存草稿，核对后点击「保存并发布」。

分类包括服务说明、常见问题、品牌规范、研究与证据、定位与实验、文案与发布、数据与复盘、运营流程。

## 发布与权限

- 保存草稿只修改编辑稿；如果已有发布版，Agent 继续读取原发布版。
- 发布时保存新的快照和版本号。页面显示当前发布范围，可展开查看发布内容与历史。
- 修改范围或 Agent 勾选后，需要发布才会生效。要立即停止读取，点击「撤下当前发布版」。
- 撤下后停止供 Agent 使用，草稿和发布历史保留。
- 到期日期按北京时间计算，当天仍有效，次日停止读取；更新到期日期后也需要重新发布。
- Lumi 只能读取已发布、未过期、可公开且明确勾选给 Lumi 的资料。
- 内部 Agent 仅读取分配给自己的已发布资料；客户产品、联系方式、付款截图和项目记录继续使用原来的项目权限。

服务资料用于解释业务和工作规范。实际报价、到账、项目进度、访问和留资数据仍以业务数据库为准。通用方法和案例不能代替市场证据，也不能跳过审批。

## 检查 Agent 会读到什么

点击页面上方「试查资料」，选择 Agent，输入问题或关键词。系统显示本次匹配到的资料、发布版本和核对日期，不调用模型。

试查只会返回该角色有权限读取、尚未过期的发布内容。没有找到时，检查发布状态、使用范围和到期日期。

## 各 Agent 的使用方式

| 使用者 | 资料用途 |
| --- | --- |
| Lumi | 公开服务介绍、常见问题、使用流程 |
| 接待报价员、客服 | 服务范围、交付与客服规范，结合当前项目记录答复 |
| Research | 研究方法与证据要求；市场事实仍由原有检索和核对流程获得 |
| Strategy | 定位与实验方法，结合已核实证据和客户确认的信息 |
| Launch | 品牌、文案和发布规范，结合已批准定位及可引用的证据 |
| Growth | 指标与复盘规范，结合程序计算的实验结论及真实数据 |
| COO、经营秘书 | 运营和报表规范，结合实际任务及经营快照 |

任务和经营报告保存本次传入模型的资料 ID、发布版本及内容片段。新发布的资料用于后续调用，不会改写已生成的报告或过去的聊天。

票据员和截图阅读员继续按固定识别规则处理当前图片，不读取共享资料库。

## 导出与开发

「导出资料」下载 Markdown ZIP，分别包含 `drafts/` 编辑稿和 `published/` 当前发布版。导出入口也需要经营者登录。

在应用目录初始化：

```bash
npm run db:migrate
npm run knowledge:seed
```

`knowledge_articles` 保存编辑稿与当前发布快照，`knowledge_history` 保留发布历史。首次部署先对目标数据库执行迁移与初始化，再发布代码。初始化可重复执行。

初版按角色、可见范围、日期和中英文关键词检索，最多传入 5 篇资料、合计最多 8000 字正文。没有新增独立向量数据库或 embedding 服务。

结构化资料包可使用 `npm run knowledge:import -- <导入包.json> --dry-run` 先校验，再选 `--draft` 或 `--publish` 导入。导入包格式为 `bundleId`、`sourceFile`、`sourceSha256` 和 `articles: [{ key, content }]`，其中 `content` 遵循现有资料字段。按包标识与条目 key 去重，重复执行不覆盖编辑、恢复撤下或发布已有草稿；已有条目的后续发布在经营台完成。整包校验后在单个事务中写资料与发布历史。
