# 源码、角色与业务衔接复测

时间：2026-11-08，Asia/Shanghai。对象：当前本地工作区，包括已有未提交修改；不代表远端部署状态。

结论：确实存在从“项目报价服务”切换为“账号 Free / Pro”后规则没有同步的情况。本轮已统一账号判定、执行权限、客户确认、办公室提示和审计记录，并启动本地任务 worker。已覆盖的核心流程未再出现阻断；这不等于所有外部服务和所有运行分支已经实测。

## 真实存在的使用端

| 使用端 | 识别方式 | 正常入口与边界 |
| --- | --- | --- |
| 免登录试用 | 浏览器中的私密项目凭据 | `/account` 创建 Free 项目；登录后可归档本浏览器有权访问的未归属项目 |
| Free 客户 | 客户会话 + 服务端有效版本 | `/account`，只能看本人项目，基础研究结束后查看机会报告与 Pro 介绍 |
| Pro 客户 | 同一客户身份 + 有效账号权益 | `/account/pro`，直接使用本人项目模块，不等待初步报价或老板开通审核 |
| 首客内部经营者 | 独立内部账号与 `fc_admin` 会话 | `/admin/login`，进入公司经营、异常处理、历史订单、知识与审计 |
| 海外公开页访客 | 无需账号 | 仅访问已发布的 `/launch/[slug]`，查看页面并自愿留资 |

Free 与 Pro 是客户权益；不能通过选择一个角色、修改链接或前端字段取得老板权限。老板登录权限名 `owner` 与历史审计身份 `founder` 表示同一个内部经营者，不是两个独立工作台角色。`isOwnProduct` 是项目属性，不是登录角色。

办公室的 Lumi、Nori、Fino、Milo、Kito、Pogo、Yuki 是工作分工与任务展示；Toby 是老板形象。它们不等于八个可登录账号。MiMo AI 是模型技术名。任务标识与人物映射见[当前角色与业务约定](../../docs/roles-and-workflows.md)。

供给方、需求方、接单交易等双边市场角色目前只有设计文档，没有可使用的对应工作端；不能宣称其业务已经互通。

## 发现及修正的衔接问题

| 问题 | 处理后的行为 |
| --- | --- |
| 旧 Pro 仅是项目级报价／密钥授权，无法支撑登录时判断账号版本 | 新增 `customer_memberships`；登录后服务端判断有效版本，过期与撤销按 Free 处理 |
| 只放开模块入口，旧审批仍要求老板先确认 | 账号 Pro 使用客户确认策略；定位、发布与下一轮仍按当前版本记录客户决定，证据检查保留，不伪造老板通过 |
| 办公室、交付清单、老板待办仍解释为等待老板 | 同步工位状态、提示与待办归属；没有下一轮假设时，Pro 复盘显示完成；不把自助模块成果显示成等待老板正式交付 |
| 自助增长复盘沿用老板动作函数，历史会记成“老板开始复盘” | 明确传入客户操作身份，审计流转记录为客户；非账号 Pro 不允许冒用客户自助复盘 |
| 登录判断和旧私密链接可能绕过账号权益语义 | 模块 action、项目归属、客户确认和 worker 均校验；账号 Pro 项目的旧访客链接也要求所属客户登录；失效后保留资料并提供客服入口 |
| 正在报价／读票据的旧任务可能与账号权益升级交错 | 当前任务完成后重新核对账号权益，允许接续到策略；研究结束时重新读取项目版本，不使用旧 Free 快照作分支判断 |
| 新流程上线后，首页、Lumi、客服和升级页仍使用旧报价说明 | 对齐 Free / Pro 当前文案；系统服务规则集中到共享常量；已有历史知识不被静默重写，旧订单规则只适用于历史项目 |
| 本机只有网页和数据库，没有 worker | 启动单个 worker，并在确认无运行任务后用最终源码重启；网页提交和后台执行分属两个进程 |
| 测试账号发布页面后可能污染真实客户经营指标 | 经营汇总排除测试账号的订单、实收、待收、访问和留资；保留实际发生的模型成本与运营执行记录，经营项目列表标注测试账号 |

价格尚未确定，因此没有添加虚构价格、扣费或假付款。账号权益订单使用 `account_active`，不生成 `payments`。历史项目密钥仍是单项目授权，不会自动变成账号 Pro；已接受的历史报价和付费项目保留原合同流程。

## 已跑通的任务交接

| 流程 | 验证内容 |
| --- | --- |
| 访客 → 客户 | 私密凭据隔离、归档不抢占别人的项目、会话过期回到原项目 |
| Free | 创建／研究／追问／补充／机会报告；需求修订保留历史，旧版本不能覆盖新记录 |
| 账号 Pro | 权益启用 → 研究 → 策略 → 客户确认定位 → 页面与声明核对 → 客户确认公开 → 数据收集 → 自助增长复盘；无报价／票据任务，无虚构老板决定或收入 |
| 权益生命周期 | Free 越权、跨账号项目、权益过期／撤销被拒；恢复权益后原项目可接续 |
| 历史报价与密钥 | 双方审批、报价版本、付款截图和实际到账分离、并发幂等、密钥开通与队列失败回滚 |
| 研究与发布 | 来源核对、溯源与声明绑定、旧页面保留至新版确认、发布时重查引用有效性 |
| 客服与经营 | 普通客服答复、投诉等升级人工处理；站会与周报生成和经营决定分别记录 |
| 可靠性 | 暂停／恢复、任务异常与重试、运行租期恢复、重复任务防止并发执行 |
| 数据口径 | 首客实收、客户增长、自有项目、测试账号、测试线索、模型成本分别处理 |

以上自动化工作流使用临时独立 PostgreSQL、stub 模型与受控来源，数据库在测试结束后清理。真实 HTTP 使用本机网页、真实客户认证和真实数据库，验证登录、归属、跳转、内部页面隔离及老板页面读取；没有通过浏览器启动示例项目的付费模型任务。

Next.js 流式跳转可能返回 HTTP 200 并携带登录跳转 meta，因此角色检查同时读取实际跳转目标；不能只用状态码把它误判成放行。

## 当前边界与后续验收

1. 本轮没有在公网部署重新执行真实 MiMo／外部搜索／Vercel 队列回调的完整链路，也没有实际支付、对外渠道发帖或真实获客验证。模型任务的确定性衔接已由隔离集成测试验证，不能据此保证实时外部来源可用或产生商业效果。
2. Pro 价格、订阅购买、退款和正式生产权益发放仍待定价方案。当前可验证版本分流与测试权益，不能视为收费已上线。
3. 双边供需市场尚未实现；现在的产品是客户使用的出海工作台及首客内部经营台。
4. 执行中范围变化、打回超限、投诉等异常仍交经营者处理。这是保留的异常路径，不应重新解释成所有 Pro 项目都要老板初步审核。
5. 本机页面仍配置示例隐私联系地址；公开交付前需替换成真实联系信息，并单独完成生产环境验收。

## 复跑

在 `firstcustomer/` 下准备本机数据库及环境变量，分别运行网页和一个 worker。迁移与初始化测试账号后：

```bash
npm run audit:source
npm run lint
npm run typecheck
npm test
npm run build
npm run verify:roles
```
